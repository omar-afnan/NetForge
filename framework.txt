You are building a competition-ready web application called NETFORGE.

PROJECT NAME:
NetForge

TAGLINE:
"A network that agents can actually debug."

CORE DESCRIPTION:
NetForge is an agent-native network troubleshooting laboratory where humans and AI agents collaborate to inspect, diagnose, explain, repair, and verify simulated network problems.

The primary purpose of this project is to demonstrate the power of WebMCP by allowing an AI agent to interact with a live network simulation through structured tools exposed by the website.

This is being built for an OpenAI/WebMCP competition. The project must prioritize:
1. Genuine WebMCP integration
2. Excellent execution and reliability
3. Clear real-world usefulness
4. Creativity and ambition
5. A polished, impressive demo experience

DO NOT build this as a generic AI chatbot.
DO NOT make fake WebMCP buttons that only simulate tool calls.
DO NOT hardcode fake agent responses.
The network simulator and WebMCP tools must actually operate on the same underlying application state.

NETWORK DIAGNOSTICS
==================================================

Implement actual diagnostic functions.

Required:

1. Ping

ping(source, destination)

Should determine whether the destination is reachable.

Return structured information such as:

- success
- source
- destination
- latency
- packet loss
- hops
- failure reason

Example failure reasons:

- Destination unreachable
- Invalid default gateway
- Interface down
- Missing route
- Link down
- ARP resolution failed

2. Traceroute

traceRoute(source, destination)

Return each hop.

Example:

PC-01
→ SW-01
→ R-01
→ R-02
→ destination

PC-01
→ SW-01
→ R-01
→ R-02
→ X ROUTE NOT FOUND

3. ARP

getARPTable(device)

Return actual ARP entries based on simulated state.

4. Routing

getRoutingTable(device)

Return:

- connected routes
- static routes
- next hops
- interfaces
- route status

5. Interface status

getInterfaceStatus(device)

6. Connectivity analysis

checkConnectivity(source, destination)

Return a detailed structured diagnosis.

==================================================
WEBMCP SAFETY
==================================================

Read-only tools:

- get_network_topology
- get_device_config
- get_interface_status
- get_routing_table
- get_arp_table
- ping
- trace_route
- check_connectivity
- get_network_issues

Modification tools:

- propose_configuration_change
- apply_configuration_change

CRITICAL:

The AI should NOT silently modify the network.

Modification flow:

AI discovers issue
↓
AI explains evidence
↓
AI proposes fix
↓
Human approval
↓
Fix is applied
↓
Network is tested
↓
Result is displayed

This human-in-the-loop behavior is a central feature of NetForge.

==================================================
AGENT WORKFLOW
==================================================

The ideal demo should work like this:

USER:

"PC-01 can't reach SRV-03. Find out why."

AGENT:

1. Calls get_network_topology
2. Calls get_device_config
3. Calls get_routing_table
4. Calls check_connectivity
5. Calls trace_route if necessary
6. Determines root cause
7. Explains the evidence
8. Proposes a fix

Example:

"R-02 has no route to 10.1.20.0/24.
The packet reaches R-02 but is dropped because no matching route exists."

Then:

"Recommended fix:
Add a route to 10.1.20.0/24 via R-03."

Display:

[Approve Fix]
[Reject]

If approved:

apply_configuration_change()

Then:

verify_fix()

Finally:

"Connectivity restored.
PC-01 can now reach SRV-03."
